# QA-Group-Problems

Shared practice problems from the QA Software Development Bootcamp. Each folder holds a problem statement, and course-mates added their own solutions as separate class files on their own branches.

## Problems

- [palindromes](palindromes/README.md): filter an `ArrayList<String>` down to the words that read the same backwards.

## What I learnt

- Setting a problem is a good test of understanding: the statement has to be unambiguous (for example, does `"ok"` appearing twice count twice?).
- A shared repository with one file per person and one branch per solution was a gentle introduction to collaborating through Git.

## What I would do better

- Include the starter code as a real file with a small test harness, so solutions can be checked automatically instead of by eye.
- Add a `CONTRIBUTING` section with the branch and naming rules, rather than burying them at the end of the problem.
